<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Pull request/source change → GitHub Actions runner | Potentially untrusted code executes checks. |
| build job → Pages artifact | Checked files cross into the deployable artifact boundary. |
| deploy job → GitHub Pages | OIDC/Pages write authority changes the public site. |
| local repository → public GitHub repository | Local history and approved assets become public. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-01-07 | Tampering | Pages artifact | mitigate | Build once, test `dist/`, upload it after checks, and make deploy consume it without rebuilding. |
| T-01-08 | Elevation | Actions permissions | mitigate | Build receives only contents read; Pages/OIDC write belongs only to the dependent deploy job. |
| T-01-09 | Information Disclosure | PR workflows/public repo | mitigate | Use no custom secrets, avoid `pull_request_target`, and scan public artifacts for placeholders/unapproved content. |
| T-01-10 | Denial of Service | failed release | mitigate | Deploy depends on successful checks; verify a failed run leaves the prior Pages release available. |
| T-01-11 | Tampering | remote setup | mitigate | Read-only preflight, explicit human approval, no force push, and stop on existing divergent content. |
| T-01-SC | Tampering | GitHub Actions and npm | mitigate | Use npm lockfile/`npm ci`; pin reviewed official actions to full commit SHAs. |
</threat_model>
