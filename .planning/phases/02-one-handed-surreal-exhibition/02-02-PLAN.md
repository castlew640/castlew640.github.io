<decisions>
- **The `→` glyph in `Read case study →` is NOT `aria-hidden`.** Phase 1 wraps decorative glyphs in
  `<span aria-hidden="true">`, which removes them from the accessible name. D-09 locks the exact
  string `Read case study →` and UI-SPEC §L.1 requires the test to assert that name, so the glyph
  must contribute to the accessible name here. Use a plain `<span>` for colour only. This is a
  deliberate, single-link departure from the Phase 1 glyph convention; every other decorative glyph
  on the page keeps `aria-hidden="true"`.
- The return link's `←` stays plain text exactly as the shipped `← Back to projects` link has it, so
  the accessible name is `← Back to the exhibition` and the §L.1 regex matches.
- `#projects` switches to `display: block` inside the exhibition layer so full-height exhibit stops
  stack normally. `#about`, `#resume` and `#contact` keep their shipped `.catalogue-section` grid.
- **`data-slug` is a real emitted attribute, not a string the scene derives from the stop id.**
  Plans 02-05 and 02-07 need an exhibit's slug at runtime: `hitPanel()` returns it and `tap.ts`
  validates it against the content schema's slug pattern before composing a selector. Two producers
  were possible — emit the attribute here, or have the scene slice `'exhibit-'` off the stop id.
  This plan emits the attribute, because the slicing variant makes the id format load-bearing in a
  file four waves downstream and leaves the security validation in `tap.ts` with nothing real to
  validate. The attribute is the producer; every consumer reads it, and no consumer reconstructs it.
- **Exhibit *variation* keys off the zero-based exhibit index, never off the slug or
  `exhibitionOrder`.** `ExhibitSection` already receives `index` from the `index.astro` map and
  passes it to the still drawing as `variant={index}` (plan 02-03); the scene's §D.4 variation uses
  the same number, derived as `n − 1` for portal `n` in the stop table (plan 02-07). One key, two
  renderings, so the drawing and the portal always vary together. `exhibitionOrder` is build-time
  content data with no runtime route into the scene and is deliberately not exposed to the client.
</decisions>
</context>
