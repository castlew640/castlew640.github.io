## Phase Goal

**Source ROADMAP `**Goal:**` line (verbatim):** "Visitors can explore a memorable surreal corridor, open the real work, and return to their place using one hand, with a complete still presentation available."

> The ROADMAP goal is not in `As a / I want to / so that` form. No user story has been invented.

**This plan's slice:** a visitor gains a real, visible still-view control and correct return behaviour — the motion policy that ACCESS-04 is defined against exists and is enforced before any scene code could ever be requested.

<objective>
Build the always-loaded client controller: the pure stop table, the motion policy gate, the scroll-to-stop derivation, hash-arrival focus, and the visible still-view toggle.

Purpose: UI-SPEC §G.1 makes the order of operations Success Criterion 4 — the policy must be decided *before* the scene chunk is requested, and downloading the renderer then freezing it does not satisfy the contract. This plan builds that gate and everything that depends on it, with no WebGL in the tree at all, so the riskiest code in the phase is proven against a scene that does not yet exist.

Output: the first client-side JavaScript in this repository, a unit-tested stop table, and a working still-view control.
</objective>

<decisions>
- **No `manifest.ts`.** RESEARCH.md's proposed build-time exhibit manifest is unnecessary: the
  controller derives the slug list from the `[data-stop]` element ids already in the document, so
  there is exactly one content source and nothing to keep in sync. The `data-slug` attribute plan
  02-02 emits is not a second source — it is the same value, rendered from the same content entry,
  so that the scene and `tap.ts` can read a slug off an element they already hold without parsing an
  id. This controller keeps deriving its **ordered** list from the `[data-stop]` ids; `data-slug` is
  read per element, never iterated for ordering.
- **`#exhibition { pointer-events: none }` is scoped to `html[data-scene="active"]`.** UI-SPEC §A.6
  (as amended by plan 02-01) states the rule unconditionally, but applied in still view it would
  also block ordinary text selection of the exhibit summary. Scoping it to the active-scene state
  fixes RESEARCH.md Pitfall 5 exactly where the problem exists and nowhere else. This task amends
  the §A.6 row accordingly.
- **The `import('./scene')` call site does not exist yet.** This plan creates the
  `enterMovingView()` gate function and nothing inside its motion-permitted branch. Plan 02-06 adds
  the dynamic import there and nowhere else, which is what makes UI-SPEC §K hook #1 a one-line grep.
</decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
