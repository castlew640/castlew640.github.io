## Phase Goal

**Source ROADMAP `**Goal:**` line (verbatim):** "Visitors can explore a memorable surreal corridor, open the real work, and return to their place using one hand, with a complete still presentation available."

> The ROADMAP goal is not in `As a / I want to / so that` form. No user story has been invented.

**This plan's slice:** the complete one-handed journey becomes possible end to end — enter, travel by arrow or swipe, open the project, read it, return to the same exhibit, reach the resume and the email, without a single chord, held key or drag.

<objective>
Build the labelled forward/back travel controls and the tap-versus-swipe discrimination that make the exhibition operable with one hand.

Purpose: UI-SPEC §E calls this the phase's hardest constraint — NAV-02, NAV-03, NAV-04, ACCESS-04 and ACCESS-05 all land here. The roadmap names the specific failure this must not have: tap selection registering after a swipe. Building it before any WebGL exists means the discrimination logic is proven on its own rather than debugged through a renderer.

Output: a real `<button>` travel nav with correct endpoint semantics, a six-condition pointer state machine that delegates to the DOM anchor, and the two e2e specs that hold them to the contract.
</objective>

<decisions>
- **The travel nav is injected as the last child of `.page-frame`, after `<main>`.** UI-SPEC §E.3
  says the buttons sit "in normal tab order, after the exhibit link of the current stop". Relocating
  a fixed element in the DOM as the visitor travels would churn focus order mid-journey, so the nav
  is injected once, after the main content, giving a stable order of content → travel controls →
  footer. Record this refinement in the summary.
- **A decorative ground-arrow mesh is not built in this phase.** The roadmap permits one as a visual
  echo, but §E.3 requires it to be `raycast = () => {}` and purely decorative, and a perspective
  mesh cannot hold a stable 56 px target. The 24 × 24 inline SVG chevron inside each button carries
  the D-14 "ground-inspired" language instead.
</decisions>

  <action>
    Create `src/scripts/exhibition/tap.ts` implementing the UI-SPEC §E.2 state machine. It accepts
    a getter for the current `SceneHandle | null` so it can ask `hitPanel(clientX, clientY)` without
    importing anything from the scene module — `three` must never be reachable from this file.

    A pointer interaction activates an exhibit only if every condition holds:
      1. duration from `pointerdown` to `pointerup` is **≤ 500 ms**
      2. the **maximum** excursion from the `pointerdown` point at any moment — tracked on every
         `pointermove`, not the end-to-end displacement — is **≤ 10 CSS px**
      3. the change in `window.scrollY` between `pointerdown` and `pointerup` is **≤ 4 px**
      4. exactly one pointer is active (`event.isPrimary === true`; a second `pointerdown` cancels
         the candidate)
      5. no `scroll` event fired during the candidate window (it cancels immediately)
      6. the `pointerup` position hits the screenshot panel, as reported by
         `sceneHandle.hitPanel(clientX, clientY)` returning a slug
    `pointercancel` cancels, and the candidate is cancelled if the pointer leaves the canvas. On any
    failure, discard silently — no visual feedback, no "almost tapped" state (§J).

    On success, navigate through the DOM only: look up
    `#exhibit-{slug} a[href="/projects/{slug}/"]` with the slug the scene returned — the `data-slug`
    value plan 02-02 emits on that exhibit's stop, read from the document rather than reconstructed
    from the stop id — and call `.click()` on it. `location.href = …`, `location.assign`, `window.open` and `pushState` are all
    forbidden — there must be exactly one navigation path per exhibit (NAV-05, §K hook #14). Compose
    the selector from the returned slug only after validating it against
    `/^[a-z0-9]+(?:-[a-z0-9]+)*$/`, the same pattern the content schema enforces, so no
    attacker-influenced string can reach a selector.

    Every listener must be registered with `{ passive: true }`, including `pointerdown`,
    `pointermove`, `pointerup`, `pointercancel` and `scroll`. This makes `preventDefault()`
    structurally impossible rather than merely promised, which is what keeps native scroll, pan and
    pinch-zoom intact (NAV-02, §K hook #2). Register no `wheel`, `touchstart` or `touchmove`
    listener.

    Gate entry on the pointer actually being over the canvas, using
    `document.elementFromPoint(clientX, clientY)` resolving to the canvas or its container. This is
    why plan 02-04 scoped `pointer-events: none` to `html[data-scene="active"] #exhibition`: without
    it, `.page-frame` — a full-width, full-document-height box at `z-index: 1` — intercepts every
    `pointerdown` over the exhibit panel and condition 6 can never be satisfied.

    Wire `tap.ts` into `start()` in `controller.ts`, passing the current scene handle getter. With
    no scene mounted the handle is `null`, condition 6 always fails, and the FSM is inert — which is
    the correct still-view behaviour, since the visible DOM link is the only way in.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pointer input → navigation | Untrusted gesture data decides whether a navigation fires |
| Scene-reported slug → DOM selector | A value produced outside the controller is used to compose a selector |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-18 | Tampering | Slug from `hitPanel()` interpolated into a `querySelector` string | mitigate | The slug is validated against `/^[a-z0-9]+(?:-[a-z0-9]+)*$/` — the same pattern the content schema enforces — before any selector is composed; no `innerHTML` anywhere. |
| T-02-19 | Tampering | An alternative navigation path bypassing the visible link | mitigate | `location.href`, `location.assign`, `window.open` and `pushState` are asserted absent from `src/scripts/`; the only navigation is `anchor.click()` on an anchor the visitor can also see and focus. |
| T-02-20 | Denial of Service | A non-passive pointer listener blocking native scroll or pinch-zoom | mitigate | Every listener in `tap.ts` and `controls.ts` is `{ passive: true }`, and no `wheel`/`touchstart`/`touchmove` listener is registered at all; asserted by grep and by a computed-`touch-action` test. |
| T-02-21 | Spoofing | A decorative mesh masquerading as the real control and shrinking with distance | mitigate | Travel controls are real `<button>` elements with fixed CSS-pixel targets; no ground-arrow mesh is built in this phase, and §E.3 requires any future one to be non-pickable. |
| T-02-22 | Repudiation | Arrow travel polluting history so Back cannot leave the exhibition | mitigate | Buttons only call `window.scrollTo`; `history.length` invariance after ten activations is an asserted test. |
</threat_model>
