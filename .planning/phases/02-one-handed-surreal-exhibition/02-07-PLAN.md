<decisions>
- **The panel is on the travel axis and above head height, which is what makes portrait work.**
  §A.1 permits on-axis solid elements only above `y = 3.0`; the panel spans `y ∈ [3.1, 5.1]`, so the
  camera at 1.62 m passes cleanly beneath it and the walkway stays unobstructed. A narrow horizontal
  field in portrait therefore costs nothing.
- **The slug comes from `data-slug`; the §D.4 variation comes from the exhibit index.** These are
  two different keys and neither substitutes for the other. `hitPanel()` reads the `data-slug`
  attribute plan 02-02 emits on the exhibit stop — it never slices `'exhibit-'` off the stop id,
  because that would make the id format load-bearing here and leave `tap.ts`'s slug validation with
  nothing genuine to validate. Variation keys off the exhibit's zero-based index (portal `n` in the
  stop table is index `n − 1`), which is exactly the number plan 02-03 passes to `ExhibitDrawing` as
  `variant={index}`, so the still drawing and the 3D portal always vary together. `exhibitionOrder`
  is deliberately not used: it is build-time content data with no runtime route into the scene, and
  keying off it would let the still and moving views disagree.
- **The figure is hidden by CSS but its `aria-hidden` is set by script.** A stylesheet cannot set an
  attribute, so the scene sets `aria-hidden="true"` on the figure when the panel texture is live and
  removes it on teardown or texture failure. `visibility: hidden` comes from the `data-scene="active"`
  CSS rule.
</decisions>
